# 可复制提示

把 `{{研究主题}}`、页数、文件名换成当前任务的实际内容。进入任务文件夹后，按顺序发给 Codex。

## 通用起步

任何任务的第一条指令：

```
请先阅读当前文件夹和 AGENTS.md，告诉我你理解到的任务目标、已有材料、缺失材料，以及下一步你建议执行的操作。先不要直接生成最终结果。
```

## 先读 Skill

安装或准备调用任何一个外部 Skill 之后、让它干活之前：

```
请先不要执行任务。请阅读这个 Skill 的 SKILL.md，并用中文总结：
1. 这个 Skill 适合解决什么问题？
2. 它需要我提供哪些输入材料？
3. 它会调用哪些脚本、工具或外部服务？
4. 它最终会输出哪些文件或结果？
5. 它明确不适合做什么？
6. 结合我的研究任务，你认为这个 Skill 是否适配？如果不适配，需要改哪些规则？
```

## 文献搜索

### 概念矩阵

```
请把下面这个研究主题拆成文献检索概念矩阵：
主题：{{研究主题}}
请输出：
1. 核心概念
2. 英文关键词
3. 同义词或近义表达
4. 可能相关理论
5. 可用于 Google Scholar 的英文检索式
6. 可用于中文数据库的中文检索式
注意：这一步只生成检索语言，不要推荐具体论文。
```

### 检索式

```
请基于上面的概念矩阵，生成 10 组检索式（英文用于 Google Scholar，必要时另给中文数据库检索式）。
要求：
1. 不要只生成一条特别长的检索式。
2. 每组检索式聚焦一个角度。
3. 每组检索式后解释它主要想找到哪类论文。
4. 输出到 search-results/search-queries.md。
```

### 真实检索

按学科换用实际已安装的检索 Skill 名称：

```
请使用已安装的真实检索 Skill，基于 search-results/search-queries.md 里的检索式进行检索。
要求：
1. 每组检索式返回前 10 篇结果。
2. 合并去重。
3. 保留标题、作者、年份、来源、引用数、DOI 或可访问链接。
4. 初步判断主题相关性。
5. 输出 search-results/literature_search_results.md 和 search-results/literature_matrix.csv。
6. 不确定的信息标记为「待核查」。
```

## 文献综述

### 主题矩阵

```
请阅读 papers/ 文件夹中的论文和 literature_matrix.csv。
先不要写综述正文，请先输出 literature_theme_matrix.md，表格包括：
1. 主题板块
2. 代表文献
3. 研究对象
4. 研究方法
5. 核心发现
6. 研究不足
7. 和我的研究问题有什么关系
注意：只能使用我提供的真实论文。不要新增文献。
```

### 大纲

```
请基于 literature_theme_matrix.md 生成综述大纲。
要求：
1. 不要按「某某说、某某说」排列。
2. 按研究主题和问题逻辑组织。
3. 每一节说明：这一节回答什么问题、使用哪些文献、最后要引出什么研究不足。
4. 输出 review_outline.md。
```

### 初稿

```
请基于 review_outline.md 和 literature_theme_matrix.md 写 literature review 初稿。
要求：
1. 每段都要有明确中心句。
2. 每个重要判断都要标注对应文献。
3. 不要写没有来源支撑的泛泛评价。
4. 不确定的地方写入 unchecked_claims.md。
5. 输出 draft/literature_review_v1.md。
```

## 数据分析

### 数据质量检查

```
请读取 data.csv 和 variable-dictionary.md。
先不要做统计推断，请先完成数据质量检查：
1. 样本量是多少？
2. 每个变量的数据类型是什么？
3. 每个变量缺失值比例是多少？
4. 是否存在明显异常值？
5. 量表变量的取值范围是否符合变量说明？
6. 输出 reports/data_quality_report.md。
```

### 分析计划

```
请基于数据质量检查结果，生成一个适合这份数据的分析计划。
要求：
1. 先做描述性统计。
2. 再做相关分析。
3. 如果变量条件允许，做回归分析。
4. 每一种分析都说明使用原因、变量选择和结果解释边界。
5. 如果某种方法不适合，说明原因，不要硬做。
6. 输出 reports/analysis_plan.md。先不要写分析代码。
```

### 写代码并运行

```
请根据 reports/analysis_plan.md 写分析代码并运行。
要求：
1. 优先使用 Python（pandas、numpy、scipy、statsmodels、matplotlib 或 seaborn）；若项目约定用 R，则改用 R。
2. 所有分析结果必须来自数据文件。
3. 保存完整代码到 scripts/analysis.py（或对应的 R 脚本）。
4. 输出描述统计表、相关矩阵、回归结果（如计划中有）到 reports/ 或表格文件。
5. 生成 figures/ 中的图，文件名要能看出内容。
6. 不要使用图片生成模型直接画统计图。
```

### 只美化、不改结果（可选）

```
请读取 scripts/analysis.py 和指定的 figures/ 图片，基于同一份数据重新导出一版更适合论文或组会汇报的图。
要求：
1. 不改变任何统计结果。
2. 只优化配色、字体、标签、图例和导出格式。
3. 同时导出 PNG、SVG 和 PDF。
4. 输出打磨后的图和 figures/figure_notes.md。
```

## 答辩 PPT

### 拆答辩逻辑

```
请阅读 final-paper.md。
先不要生成 PPT，请先输出 defense_logic.md，包括：
1. 这篇论文的研究问题是什么？
2. 为什么这个问题值得研究？
3. 文献综述最后引出了什么不足？
4. 本文的方法设计是什么？
5. 主要发现是什么？
6. 创新点是什么？
7. 答辩时最可能被问到的问题有哪些？
```

### 大纲（先确认再出片）

```
请基于 defense_logic.md 生成约 12 页的答辩 PPT 大纲。
要求：
1. 每页包括：页标题、核心信息、建议图表、讲述重点。
2. 结构包括：研究背景、研究问题、文献基础、研究方法、主要发现、创新点、不足与展望。
3. 不要直接生成 PPT，先输出 outline.md 等我确认。
```

### 生成 PPT

把 Skill 名称换成实际已安装且已读过的 PPT Skill：

```
请使用已安装的 PPT Skill，把 defense-ppt/final-paper.md 做成约 12 页的答辩 PPT。
要求：
1. 先阅读 AGENTS.md、defense_logic.md 和 outline.md。
2. 如果 outline.md 还不适合答辩，请先提出修改建议，不要直接生成 PPT。
3. PPT 使用科研答辩风，页面简洁，减少大段文字。
4. 必须保留论文中的关键图表，不要编造新数据。
5. 生成或更新 outline.md、speech.md 和最终 .pptx，输出到 ppt-output/。
6. 每页备注区写入对应讲稿。
```
